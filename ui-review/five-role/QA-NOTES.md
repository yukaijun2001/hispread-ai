# OPERATOR / FINANCE 补充验收

本补充报告包含48个本地截图Tab：31个可达页面、16个菜单或业务弹层，以及1个使用临时账户验证的财务审核界面。没有提供线上运营或财务账号，因此不计算像素一致度，也不判定视觉还原通过。原60视图配对报告保持在上级目录。

两角色各测试30个路由，共60个：OPERATOR33权限有15页可达、15页拒绝；FINANCE28权限有16页可达、14页拒绝。与权限目录预期全部一致，无runtime错误，最后页面GET失败数0。6个禁止的运营/财务/系统写探针全部返回403，未创建业务数据。

运营验证了新增供应商、项目、CCMAX目标、工作台展示配置和报价详情抽屉；报价原始记录是已退回，详情已核对，未伪称存在待审报价供审核。财务验证了金额录入、新建结算、汇率新增、供应商平台配置只读以及账户审核。平台配置字段全部disabled，保存按钮由原代码隐藏；财务报价没有审核控件。工作台仅quote.read无quote.review时显示“查看报价”，没有settlement.read时不显示结算入口。

监控来源列表最初返回403，随后按资源配置/监控配置的OR权限修复，重启后GET200并重拍相关页面；原失败记录保存在previousFailedRequests。没有篡改历史QA，也没有保留失败状态冒充最终状态。

临时PENDING账户通过供应商真实本地API创建，财务仅打开审核控件，未提交审批。完成后按临时id+qaMarker严格删除account/account-secret两行，清理前2行、清理后0行，既有账户数据保持。详见docs/five-role-account-review-qa.json。

截图采集为1920×1000。所有图片内嵌到report.html；技能原渲染器对无design截图不展示图片，本项目在产物中补上对应Tab的原始本地截图并移除默认“本页100分”，未修改技能源码。DOM、菜单、按钮、接口和权限结果见docs/five-role-browser-qa.json；截图输入没有DOM，结构0项不等同0缺陷。
