# 上号与交付任务

2026-11-14 按产品定位收敛：本站负责供应商上号、账号交付与报价；上游网关负责请求运行、容量监控和调度。

该次调整版本 `0.8.123`；资源上游的后续精简见 [0.8.124 功能范围](resource-upstream-scope.md)：

- 「上号与交付任务」位于业务导航，展示已有的提交、OAuth 兑换、重新授权、凭据刷新、维护和代理操作回执。列表只读，不复制凭据；权限沿用资源的供应商、成员、项目和运营归属范围。
- 「查询原结果」查询持久化的原操作，沿用原操作幂等键与关联检查；不重新生成 OAuth 链接、不重放创建。确认失败后的重新提交仍在原资源页面按原有规则操作。
- 最高管理员可选择启用交付状态同步。默认关闭，周期为 10–1440 分钟；只刷新账号状态与健康，不扫描请求日志、不更新费用和权重、不写日账或结算记录。现有单资源手动查询与维护流程仍保留。
- 已通过报价在未来 7 天内到期时，工作台显示站内待办。此提醒读取现有报价，不新增任务、报价或自动批准；续期由用户手动提交并走原审核流程。
- 结算需供应商明确确认或提出异议。建议核对时间到期不会自动确认；到期后仍能手动确认，已确认历史单据不回退。

不再执行费用日账采集、网关 RPM/TPM 监控、自动优先级轮换、自动报价续期、企微机器人外发及自动财务确认。旧写入/执行接口返回 `410 TASK_RETIRED`。已有运行、账单、报价、审计、机器人加密配置与监控源保留历史；不在迁移中发送网络请求、恢复权重或确认资金。以前轮换留下的权重快照仍允许最高管理员显式调用恢复接口，不能创建新一轮扶持。

升级迁移 `V3__delivery_task_scope.sql` 停用所有已有定时计划（包含状态同步，须管理员重新选择启用），清除下次执行时间，将遗留运行中记录标为中断；停用旧监控源和报价续期标记，保留版本增量和历史。

接口：`GET /api/delivery-tasks`（分页、状态/类型/待核对筛选）、`POST /api/delivery-tasks/{id}/reconcile`；状态同步继续使用原 `/api/system/scheduled-tasks` 配置协议，历史列表使用 `GET /api/system/scheduled-tasks/history`。

验证：独立 PostgreSQL 中全量后端 **215 项通过**，包括上号/OAuth、交付任务租户和成员隔离、凭据脱敏、旧任务执行阻断、过期账单人工确认、状态同步不扫描请求日志，以及已有数据的 V3 升级测试。前端类型检查及生产构建通过；`deploy.sh` 的 **17 个隔离场景通过**。本地浏览器验证了业务导航、新任务表、待核对筛选、默认关闭的同步设置、工作台到期提醒和监控入口移除。没有操作生产服务器或真实上游。

`scripts/verify-background-config.py` 为当前本地浏览器夹具；`verify-background-jobs.py` 与 `verify-background-rotation-restart.py` 描述被淘汰的自动任务验收，不再作为本版本验证入口。旧验收报告保留原日期及结果，不能据此重新开启已退出的任务。
