# 本地实现的五角色职责与数据边界

本文件记录本项目新增的专业权限决策。原站证据仅提供前端权限码、页面分支和接口调用，未提供生产内置角色授权策略；以下职责收紧是用户本轮明确要求的本地设计，不能描述为已逆向证实的原站安全规则。

| 主身份 | 数据范围 | 允许职责 | 明确禁止 |
| --- | --- | --- | --- |
| ADMIN | 平台管理范围 | 系统配置、供应商归属、主账号和角色、平台审核、基础项目与接口配置 | 审核自己提交的报价/账户/付款；代供应商确认结算金额或确认到账 |
| OPERATOR | 仅 `ownerUserId` 等于本人ID的已归属供应商；未分配供应商不可见 | 维护归属供应商资料并提交复核、审核他人报价、资源业务元数据和交付、业务代理、运营数量报表 | 供应商审核/启停/账号绑定/改归属；项目或全局资源接口写；原始凭据；任何财务金额/付款；通知发布、审计、全站导出 |
| FINANCE | 允许的账务与付款范围 | 收款账户独立审核、账务录入、结算创建、付款申请、他人付款审核、审核后线下登记、汇率只读、财务报表 | 供应商/项目/报价/资源写；新增或更改收款账户；完整账号；汇率写；实时通道执行；系统与支付通道配置 |
| SUPPLIER | 仅自身tenant | 自身资料、报价、交付、代理、团队、账户申请及变更、结算确认与到账确认 | 其他tenant；跳过平台审核直接改付款账户或款项；平台管理操作 |
| SUPPLIER_AGENT | 本人资源，或被授权部门的组员资源，并同时满足当前项目授权 | 获授权交付与日账；部门管理员仅在本组、在自己项目授权以内继续分配 | 账号创建/密码/启停、部门分组变更、跨组授权、超出本人项目；项目撤销后继续读取旧资源 |

付款遵守申请与审核分离：线下付款提交创建 `PENDING` 申请，不增加已付金额。另一位有权限的FINANCE或ADMIN独立审核后进入 `APPROVED`，再携带版本及真实凭证登记结果。`createdBy` 为申请者、`reviewedBy` 为审核者、`recordedBy` 为线下登记者。申请人不能审核自己的申请，ADMIN同样受限；登记人可为申请人或第三人，但必须已经独立审核。

当前本地默认职责权限数量：ADMIN 61、OPERATOR 17、FINANCE 22、SUPPLIER 28、SUPPLIER_AGENT 10；部门管理员可在成员上限内取得团队项目分配权限，不改变身份。

运营报表独立访问 `/api/reports/operations`，仅返回归属供应商、报价和资源数量以及项目/供应商分组数量。前端按权限选择运营报表分支，不调用财务 `reports/overview`，不显示金额、币种、消耗或原始凭据，不提供全站CSV导出。

2026-11-12 资源上游验收补充：已归属运营的资源列表、详情和维护回执也必须过滤累计费用、币种及嵌套报价快照；项目/创建人资源汇总不返回实际金额。健康状态、资源数量和任务成功/失败数量保留。报价审核页面仍按既有 `quote.read/quote.review` 授权执行。本次通过真实接口发现投影缺口并补充服务端回归；修复部署前不得将运营资源金额边界标记为验收通过。

主身份只能是五个内置角色。自定义角色只能作为附加角色，`scopeType` 为OPERATOR、FINANCE、SUPPLIER或SUPPLIER_AGENT之一；新增时必须选择，之后固定。附加角色必须与主身份同scope，权限必须是该主身份职责上限的子集，不能经角色合并变成管理员、平台身份或扩大tenant范围。角色编辑器使用服务器返回的 `allowedPermissions` 作为可选上限，超出项禁用；已存在无scope的旧自定义角色必须由管理员明确合法职责后才能生效。

前端导航、控件和文案只辅助正确操作，服务器仍须独立执行可见范围、职责上限、申请审核分离、版本校验和敏感字段投影。浏览器QA会另行记录实际角色可达/拒绝、运营报表网络请求、受限角色控件及两账号付款流程；不以隐藏按钮代替授权验证。

当前默认授权数量：ADMIN61、OPERATOR17、FINANCE22、SUPPLIER28、新建SUPPLIER_AGENT10。旧成员迁移只保留原授权与新上限交集，本地原成员实际8项，不自动补齐新权限。权限码数量仅用于配置核对，数据范围、状态、版本和审核人校验同样在后端独立执行。

角色和用户授权在security-role-policy-v3迁移时收敛，跨职责或无职责标记的旧附加角色会撤销；管理员主动缩减后的权限保留。旧会话因版本变更失效，需重新登录。运营原本未分配供应商的账号保持未分配，系统不为展示效果自动扩大范围。最高管理员账号不能通过角色编辑削减权限；停用或更换身份时保留至少一名启用管理员；密码重置后服务端强制改密。

自动回归：48项真实PostgreSQL测试通过。五角色浏览器检查110个路由场景，运行错误0、失败页面请求0；运营通过管理员真实分配后可见该临时供应商，另一运营返回404且报表不包含该对象，测试后清理。最终索引见security-hardening-validation.json和../ui-review/permission-hardening/report.html。

本地历史种子成员本轮实际有效权限为8项：迁移保留旧账号已有授权与新默认10项的交集，旧账号未有的 `proxy.write`、`file.write` 不自动补授。新建成员默认10项，职责上限另含获授权部门管理范围；权限数量本身不是验收目标。旧会话应重新登录后读取新策略。
