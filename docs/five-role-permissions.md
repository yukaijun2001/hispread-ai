# 五个内置角色与权限

五个内置身份均有独立登录和服务端权限边界。页面复用恢复的 Vue 平台/供应商组件，以 `supplierId` 和 `permissions` 决定菜单及动作；权限名称不等于最高管理员身份。

| 身份 | 标识 | 默认范围与职责 | 默认不开放 |
| --- | --- | --- | --- |
| 平台最高管理员 | ADMIN | 全平台业务、账号角色、系统参数和支付通道配置 | 最高管理员权限不能在角色编辑中削减 |
| 平台运营 | OPERATOR | 供应商资料与审核、运营归属、项目、报价审核、资源与接口、代理、通知、运营统计、报表及审计 | 财务账户、日账/结算/付款操作、系统账号角色、全局参数、支付通道配置 |
| 财务人员 | FINANCE | 供应商/项目/报价只读、收款账户审核、金额录入、日账、结算、付款登记与审核、汇率、报表及审计 | 供应商/项目/报价/资源的运营写操作、系统账号角色、全局参数、支付通道配置；不代替供应商确认金额或到账 |
| 供应商主账号 | SUPPLIER | 本供应商的资料、报价、交付、部门成员、结算与收款 | 跨供应商业务和平台系统管理 |
| 供应商子账号 | SUPPLIER_AGENT | 本人或获授权部门的交付和日账，以及被分配的项目 | 主账号财务、普通成员的部门管理、平台系统管理 |

平台运营默认33个权限、财务人员默认28个权限；精确配置以 `backend/src/main/java/com/hispread/ai/RolePolicy.java` 为准。原生产前端证据包含动态角色和权限码，但不包含服务端为 OPERATOR/FINANCE 分配的默认集合。此处是按恢复页面和业务职责落地的本地默认策略，不声称获取了原站私有配置。

平台角色跨供应商读取已获授权的业务数据；供应商角色继续按 `owner_id` 隔离，子账号进一步按创建者、部门和项目授权约束。运营可看报表汇总，不因此获得结算详情和付款写权限。平台运营可配置资源接口，不能配置全局系统参数或资金通道。管理员可编辑角色权限和分配自定义附加角色；服务端依据当前角色及授权控制业务入口，最高管理员专属入口继续校验最高管理员身份。

新增本地账号是 `local_operator` 和 `local_finance`。初始化密码分别存于 `backend/.env` 的 `OPERATOR_PASSWORD` 和 `FINANCE_PASSWORD`，文件权限600且被忽略。运行 `python3 scripts/credentials.py` 查看五个账号名称；在自己的终端添加 `--passwords` 查看本地初始化密码。首次启动创建缺失账号，重启不重置已有密码。

旧版本只有空权限的 OPERATOR/FINANCE 内置记录会执行一次受限默认策略迁移；管理员后来修改或主动清空的角色权限不会被重启覆盖。角色权限修改同步所有基础角色/附加角色关联账号，并使旧会话失效；变更基础角色会重新计算权限，避免保留原角色权限。

外部 CCMAX、OAuth、支付执行与代理探测仍需真实上游配置。角色获授权后可进入对应界面；没有配置的外部执行仍返回明确503，不能理解为已实际发起支付或完成授权。
