# 部署与验收数据清理

日期：2026-11-16（Asia/Shanghai）。用户授权在服务器手动执行部署及清理，明确要求不创建备份。

## 执行方式

服务器现有项目目录首次使用时先更新本地脚本：

```bash
git pull --ff-only
./deploy.sh --clean
```

脚本会自动拉取最新代码、构建、部署并通过健康检查后调用清理器；普通 `./deploy.sh` 保留数据。清理仍沿用部署的项目名、生产环境文件和端口覆盖，整个过程持有同一部署锁。

## 范围

保留原平台管理员及密码、管理员API密钥、角色权限、系统参数、全局上号规则、NewAPI/CCMAX及其他已配置上游目标、支付配置、汇率和非测试品类。

删除本站唯一验收供应商及测试账号、测试项目、报价、资源和凭据本地记录、金额及任务历史、导出、验收通知和附件；旧会话注销。只允许供应商及项目有明确验收标记、其他账号名以qa_开头的全验收环境。其他供应商、正式账号、未知数据类型、活动任务或不匹配附件均会使清理停止。清理不发送上游请求，不归档或删除真实上游账号、渠道、密钥。

不创建数据库、附件或其他备份。清理在单个数据库事务中校验全部记录指纹和保留记录，附件只按核对后的UUID清单删除；不会删除数据卷或改变管理员密码。提交前拒绝会恢复服务；提交后附件/重启失败或提交结果不明时保持服务停止并返回失败，需核对状态再启动。

## 验证

部署脚本20个隔离场景通过。清理器11项回归通过，覆盖普通部署无清理、部署成功后调用一次、错误传播、无备份、范围拒绝、文件不匹配、数据库回滚、响应丢失、附件失败、管理员及配置完整保留。数据库测试使用新建的独立PostgreSQL数据库并在结束时删除。未执行服务器清理，未访问真实上游。
