# New API 验收问题修复

2026-11-10 真实验收发现：渠道148可以关联、读取用量、测试模型，但启停被上游拒绝，批量优先级返回不支持，页面缺少关联入口且按CCMAX草稿展示。

## 修复内容

- 启停使用New API专用状态端点，写入后读取原渠道确认。仅专用端点404/405时兼容旧接口；认证错误和success=false不回退。状态不一致保持UNKNOWN。
- 批量优先级按已有前端接口处理范围、预览、执行、幂等重放、只读核对和仅重试失败项。单批最多100条，同一目标，执行前核对版本及固定映射。
- 管理员可以在资源列表点击「关联 New API 渠道」，选择现有本地资源和资源目标，填写数字渠道ID。关联已有渠道不代表新建交付，不修改真实账目。
- 已关联资源显示「New API 渠道」「已有渠道已关联」、实际启停状态、原始配额及余额；零值正常显示。详情支持查询、连通性测试、确认启停和管理员优先级。
- HTTP公网访问缺少crypto.randomUUID时，使用浏览器crypto.getRandomValues生成UUID，防止资源弹窗创建失败。

## 验证记录

- `mvn -q package`：123项测试，0失败、0错误、0跳过；包括真实PostgreSQL事务、本地HTTP协议服务、状态专用端点及旧版回退、写后状态不一致、优先级预览/执行/重复start/只读核对、非管理员拒绝及重复关联拒绝。
- 前端`npm run check`与`npm run build`通过，继续生成静态压缩产物。
- ego-browser在本地服务中回放真实验收场景，验证关联入口、零配额显示、详情、停用/恢复与优先级提交；另检查窄屏详情和HTTP200业务失败提示。浏览器使用隔离接口回放，未修改线上渠道148。

## 部署与复测

在服务器现有仓库目录执行：

```bash
./deploy.sh --origin http://152.53.83.250:10001
```

脚本自动拉取origin/main、构建镜像、更新容器并检查健康。保留现有.env.production、数据库及上传卷。只暴露前端10001端口。已经关联的渠道148会通过读取投影自动识别，无需重新建立验收记录或改写数据库。

部署后强制刷新，在资源列表找到「验收专用-NewAPI-渠道148」，进入「渠道详情」复测启停与优先级。生产复测通过前，不把本地协议测试作为真实上游成功证明。
