## 已修复的问题

1. **启停、恢复、归档未决防重**：前端保留本次请求编号和原操作 ID，超时、响应丢失或任何未确认条目都不换键再次发送。新增 `GET /api/resource-lifecycle-jobs/by-request/{requestKey}` 查询本地原记录；随后只能显式核对原操作。服务端按资源排序加事务锁，同批任一结果未确认时，拒绝该批次任何资源的新维护操作，返回 `409 RESOURCE_LIFECYCLE_UNRESOLVED`。同原编号重放仍返回原记录。冲突只在原操作通过可见范围校验后返回 ID，未知状态、聚合不一致或请求自报状态不能解除阻断。
2. **维护结果展示与历史保护**：不再把 UNKNOWN/PARTIAL/FAILED 统一显示为“后台处理中”或成功；详情弹窗内展示状态与错误，保留原查询入口。确认终态才允许后续动作，查询失败继续保留未决状态。已确认终态的原操作核对直接返回保存的回执，不再访问上游或回写资源，避免查询旧暂停记录影响后来的恢复状态。原生详情能力查询绑定当前 resourceId，避免读到其他默认目标或供应商能力。
3. **日账导出**：按核对/结算状态分别汇总，待核对金额不会混入已确认应付。CSV/XLSX 增加“已确认应付、核对状态、结算状态、待核对计算金额”；原始数量和快照合计在汇总前计算。旧预览使用保存的旧表头；过期导出读取呈现 EXPIRED，不伪装可下载。
4. **金额来源防重**：相同来源单号在报价计价和直接金额之间切换重放返回 409，避免接口跳过旧记录后表单误报新计价成功。
5. **固定独立审核**：移除“允许同一人提交并审核”控件和响应字段，伪造 true 返回 `410 REVIEW_POLICY_FIXED`。旧客户端 false 兼容忽略，部分策略保存保留其他已配置密码/会话策略；历史字段保留存储，不再发布或生效。管理员同样不能自审。

本轮不扩展网关能力、不新增自动调度或自动出款，无数据库迁移，不清理既有资源、账务、用户或凭据。
